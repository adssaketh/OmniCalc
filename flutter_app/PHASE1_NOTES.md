# Phase 1 - Foundation (engine port + golden harness + CI)

## What changed
- `flutter_app/` (new): the Flutter project. It sits in a sub-folder so the existing Capacitor `android/`, `package.json` and `src/` (the specification) stay untouched on this branch. Android scaffolding is generated by CI with `flutter create` (application id `com.saketh.omnicalc`).
- `lib/engine/js_number.dart`: JavaScript-exact `toString`, `toFixed`, `toPrecision`, `toExponential`, `parseFloat`, `Math.round`, `%`, `Math.pow`, `sign`, `cbrt`, `log10`, `log2`, `sinh/cosh/tanh/asinh/acosh/atanh`.
- `lib/engine/evaluator.dart`: line-by-line port of `src/engine/evaluator.ts` (sanitize order, phone-style percent, regex tokenizer, multi-arg pre-pass, shunting-yard, RPN, numerical derivative/integral/limit/sum/product, `formatResult`, `evaluateFunction`, y-equation state).
- `lib/engine/calc_error.dart`, `lib/engine/types.dart`: error type (messages identical to the TS) and `AngleMode` (deg/rad only, as in the source).
- `test/golden/*.json`: all 17 golden files from your `golden.zip` (plus the zip itself, `golden.zip`).
- Tests: `evaluator_golden_test` (679 vectors), `evaluate_function_golden_test` (52), `format_golden_test` (47), `round_golden_test` (16), `js_number_test` (unit tests).
- `tools/gen_vectors.ts` + `tools/vector_inputs/`: regenerates the Phase 1 vectors from the real TS engine. `--check` mode compares with the committed files.
- `.github/workflows/flutter-ci.yml`: analyze -> test -> release APK -> upload (signed with the same four secrets if present). Runs on pushes to `flutter-rewrite` only.

## Verified here (honest status)
- `npx tsx flutter_app/tools/gen_vectors.ts --check`: the repo's TypeScript engine reproduces `evaluator`, `evaluate_function`, `format` and `round` exactly (679 / 52 / 47 / 16 vectors). So the zip really is the oracle for this source.
- The number-formatting algorithm used in `js_number.dart` was mirrored in JavaScript (BigInt) and compared with V8: 100,355 checks (all 47 golden format vectors + 20,000 random values x 5 formats), 0 mismatches.
- **NOT verified: any Dart code.** The sandbox cannot reach the Dart/Flutter SDK hosts, so `flutter analyze` and `flutter test` have not been run. Nothing here is claimed to compile or pass yet.

## Run it yourself
```
cd flutter_app
flutter pub get && flutter analyze && flutter test
```
(CI uses `flutter analyze --no-fatal-infos`; plain `flutter analyze` also fails on info-level lints.)
Regenerate vectors (repo root): `npx tsx flutter_app/tools/gen_vectors.ts`

## Parity doubts to watch when the tests first run
1. `math.sin/cos/tan/exp/log/pow` use the platform libm on Android and the host libm in `flutter test`; V8 uses fdlibm. A 1-ulp difference could flip a 12-digit rounding in the calculus kernels. If a vector fails like that, port the fdlibm function.
2. `jsLog2` and `jsCbrt` are accurate but not bit-identical ports of V8 (exact on powers of two / perfect cubes).
3. `jsLog10` snaps to exact integers for 10^0..10^22 (fdlibm guarantees this); other inputs use the fdlibm formula with the platform `log`.
4. `rand()` / `randInt` are random and have no vectors.
5. `flutter_lints` may report info-level style hints; none should be errors.
